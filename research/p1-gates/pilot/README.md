# 부표 훈련에서 첫 관문 검사까지

혼자 두 번에 걸쳐 직접 점검하려면 [개인 점검 시작 안내](START_HERE.ko.md)를 사용하세요. 고정 부호로 연습하며 첫 방문 뒤 점수와 정답을 보류합니다. 이 문서의 무작위 두 집단 리허설과는 다른 로컬 데이터 파일을 사용합니다.

고정 부호를 보면서 직접 조종한 경험이, 같은 정보를 화살표로 보고 연습한 경험에 비해 **새 목표에서 고정 부호를 사용하는 첫 수행**에 도움이 되는지 측정하는 첫 세션입니다. 두 집단 모두 같은 부호 설명과 식별 연습을 받습니다. 훈련할 때의 표시만 바꾸고 첫 검사에서는 같은 화면을 씁니다. 현재 확인한 증거는 개발자용 로컬 리허설과 합성 소프트웨어 검증입니다. [관문 문항의 물리 검증과 선별](../README.md)

## 한 세션에서 하는 일

| 구간 | 화면과 진행 | 기록 |
| --- | --- | --- |
| 공통 연습 | 같은 부호 설명을 읽고 여덟 방향을 한 번씩 식별합니다. 각 응답 뒤에 정답을 알려 줍니다. | 식별 응답과 정답 수 |
| 부표 유지 | 고정 부호 또는 화살표를 보면서 키보드나 터치로 부표를 중앙에 유지합니다. 같은 두 흐름에서 각 600틱, 30초씩 조종합니다. 구간 사이에는 직접 다음 훈련을 시작합니다. | 매 틱의 직접 입력, 중심 이탈 거리, 훈련 구간별 RMSE와 전경 진행 시간 |
| 첫 전이 검사 | 양쪽 집단에 고정 관측소와 고정 부호를 제시합니다. 도착·방류 목표를 섞은 A형 또는 B형 16문항을 하나씩 풉니다. 선택을 확정하면 다음 문항으로 넘어갑니다. | 첫 선택, 문항별 경과 시간, 전체·목표별 정확도 |
| 경험과 결과 | 선택할 때 살펴본 점을 자유롭게 적거나 건너뜁니다. 이후 첫 점수와 문항별 정답을 확인하고 자기 결과 JSON을 내려받을 수 있습니다. | 선택적 경험 서술과 완료 상태 |

네 세션을 한 묶음으로 삼아 **훈련 표시 2종 × 검사형 2종**을 한 번씩 무작위 순서로 배정합니다. 세션을 새로고침해도 배정은 유지됩니다. A·B는 서로 같은 장면에 목표를 교차시킨 첫 검사형입니다. 한 세션에는 한 형식만 사용합니다. 훈련 시드 710003과 710029는 관문 시드와 겹치지 않습니다.

## 실행

Python 3.12 환경에서 저장소 루트를 기준으로 실행합니다. 기존 개발 환경이 있으면 마지막 명령부터 실행할 수 있습니다.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
.venv/bin/python -m pip install --no-build-isolation --no-deps -e .
.venv/bin/python research/p1-gates/pilot/app.py serve
```

같은 기기에서 [첫 세션 열기](http://127.0.0.1:8012/)를 사용합니다. 시작 버튼을 누르면 로컬 SQLite 파일에 새 리허설이 생성됩니다. 기본 경로는 `runs/p1-pilot/developer.sqlite3`입니다. 도중에 닫거나 서버를 다시 시작해도 같은 주소·브라우저·데이터베이스에서 마지막 확정 상태를 불러옵니다. 중단 상태에서는 훈련 신호를 가립니다. 브라우저의 로컬 세션 쿠키가 만료되거나 삭제되면 이전 세션 연결이 끊깁니다.

완료한 첫 검사들의 집계는 아래 명령으로 확인합니다. 합성 검증은 `--kind synthetic`으로 실행하며 별도 데이터베이스와 증거 표기를 사용합니다.

```sh
.venv/bin/python research/p1-gates/pilot/app.py summary
```

## 측정값이 의미하는 것

- 주 지표는 한 세션의 첫 16문항 정답률입니다. 훈련군별 평균을 구한 뒤 **고정 부호 − 화살표** 차이를 퍼센트포인트로 계산합니다. 화면에는 문항별 정답을 마지막에 공개합니다. 분석에서는 경험 서술을 생략하거나 남겨 두었더라도 16개 선택을 모두 확정한 세션을 포함합니다. 각 집단의 시작·첫 검사 완료·전체 완료 수도 함께 보고합니다.
- 같은 시뮬레이터와 인과 추정기 `rw-kalman-v1`, 고정 부호기 `polar8-v1`을 사용합니다. 신호는 두 표시에서 같은 여덟 채널 강도, 불확실성, 누락, 갱신 상태와 신호 나이를 갖습니다. 훈련 중 센서·부호기는 목표나 정답을 입력으로 받지 않습니다. 부표 조작에는 사용자가 입력한 두 축의 추진력만 적용합니다. 기준점은 고정된 중앙 (0, 0)입니다. [표시와 동역학](../../../docs/METHODS.md)
- 훈련량은 조건마다 **활성 시뮬레이션 시간 60초**로 고정합니다. 기본 간격은 50ms입니다. 중지하거나 탭을 벗어나면 새 조작을 보내지 않고 신호를 가립니다. 이미 보낸 조작은 한 틱 반영될 수 있습니다. 각 구간의 `foreground_s`는 브라우저가 실제로 진행한 입력 사이 간격의 합입니다. 네트워크와 그리기 지연으로 시뮬레이션 시간과 차이가 날 수 있습니다. 첫 검사 문항의 `elapsed_ms`는 서버가 문항을 열고 응답을 확정하기까지의 시간으로, 창을 떠난 시간도 포함합니다.
- 상태·조작·선택은 원자적으로 로컬에 저장합니다. 같은 응답을 재전송해도 선택이 중복되지 않습니다. 재시작 시 마지막 훈련 상태는 기록된 직접 입력으로 재생합니다. 서버가 반환하는 첫 검사 자료는 현재 한 문항의 목표·지도·표시 신호입니다. 전체 정답표는 오프라인 평가 파일로 관리합니다. 공개 저장소에는 문항이 공개되어 있어 사전 노출은 실제 파일럿에서 확인할 요소입니다.

## 검증과 해석

네 훈련·검사형 조합을 브라우저에서 각각 전체 길이로 실행했습니다. 합성 응답이 항상 왼쪽을 선택했을 때 네 세션 모두 8/16이었고, 두 집단의 채점 차이는 0퍼센트포인트였습니다. 이 값은 균형 잡힌 채점표가 의도대로 작동하는지 확인한 대조입니다. 각 구간은 600틱으로 끝났고 여덟 구간의 브라우저 전경 진행 시간은 30.13~30.38초였습니다. [브라우저 집계](verification.json)

전체 길이 API 검사에서는 조건별로 서로 다른 추진을 가했는데도 1,200틱의 신호와 갱신 틱이 일치했습니다. 저장된 개별 입력으로 적분한 부표 궤적과 구간별 중심 이탈 RMSE를 대조했고, 서버 재시작·중복 입력·문항 도중 새로고침과 완료 전 정답 비공개를 확인했습니다. 첫 관문 검사에 나타나는 16개 문항은 같은 형식이면 두 훈련 조건에서 동일했습니다. 전체 자동 검사 114개가 통과했습니다. 별도의 360px 터치 모의 입력에서 버튼을 누르면 추진이 적용되고 손을 떼면 0으로 돌아왔습니다.

```sh
.venv/bin/python -m pytest -q tests research/p1-gates/test_gate_items.py research/p1-gates/pilot/test_pilot.py
.venv/bin/python research/p1-gates/pilot/verify_browser.py --out runs/p1-browser --chromium /path/to/chromium
```

두 번의 30초 훈련은 첫 리허설의 설계값입니다. 사람에게 충분한 연습량인지는 별도로 측정해야 합니다. 다음 실측의 판단 기준은 식별 연습 정확도, 직접 조종 수행, 첫 관문 점수의 바닥·천장 분포와 두 훈련군의 차이입니다. 실제 사람에게서 차이가 관찰되더라도 고정 부호에 익숙해진 효과가 포함됩니다. 누가 얼마 동안 숙련을 유지하는지는 정해진 간격 뒤 **처음 보는 장면**을 푸는 재검사에서 평가합니다. 같은 브라우저의 중단 복구는 첫 세션 안의 한 번의 시도로 기록됩니다. [연구 설계 및 사람 대상 수집 범위](../../../docs/PROJECT_SELECTION_AND_PROTOCOL.md)

## 두 번 방문하는 개인 점검

`--self-check`는 한 로컬 데이터 파일에 고정 부호 훈련 한 번과 A·B 중 무작위로 뽑은 첫 검사 한 형식을 배정합니다. 재시작·재접속은 이 기록에 이어집니다. 첫 검사 마지막 응답과 재검사 첫 문항을 연 시각으로 실제 간격을 계산합니다. 첫날의 선택 확정 뒤 남긴 메모 시간도 이 간격에 포함됩니다. 24시간은 목표값이며 일찍 시작한 경우 내보내기에 표시됩니다. 마지막 묶음까지 응답하고 선택적 메모를 넘긴 뒤 첫 검사·재검사·배치 진단을 별도로 채점해 보여 줍니다. 파일에는 사전 노출 응답, 두 번의 메모, 세 묶음의 문항별 선택·경과 시간, 원래 훈련 지표가 들어갑니다. 개인 사용성 점검은 `participant_kind=developer`로 저장하며 두 집단의 비교 집계에 넣지 않습니다.

로컬 API 검사에서 첫날 이후 소프트웨어 시계를 25시간 뒤로 옮겨 재접속·채점·기록된 간격을 확인했습니다. Chromium에서는 1050px로 첫 세션을 진행하고 쿠키를 지운 뒤 360px로 다시 열어 두 번째 방문과 JSON 내려받기까지 검증했습니다. 브라우저 실행은 재검사를 즉시 시작해 이른 방문이 표시됐습니다. 두 실행 모두 합성 입력을 사용했습니다. [브라우저 집계](../followup/browser-verification.json) · [재검사와 진단 문항 설계](../followup/DESIGN.md)

Linux에서 공백이 있는 새 폴더에 실행 파일로 환경을 설치하고 합성 연습을 시작했습니다. 서버를 종료한 뒤 패키지 인덱스 접속을 끄고 다시 실행해 같은 연습 응답 화면이 열린 것을 확인했습니다. macOS Finder에서의 실행은 실제 Mac에서 확인할 항목입니다.

```sh
.venv/bin/python research/p1-gates/pilot/verify_browser.py --self-check --out runs/return-browser --chromium /path/to/chromium
```
