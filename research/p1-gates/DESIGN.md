# P1 관문 문항의 개발·확인 설계

이 연구는 같은 흐름을 두 목표에 쓸 수 있는 문항을 만드는 소프트웨어 실험입니다. 두 목표의 선택 결과를 시뮬레이션으로 각각 채점한 뒤, 화면이나 부호에서 얻을 수 있는 단서를 점검합니다. 개발용 두 지도에서 아래 설계를 정하고, 별도의 네 지도와 새 시드로 한 번 적용합니다.

| 요소 | 고정한 설계 |
| --- | --- |
| 장면 | 2차원 Hidden Flow의 중앙 관측소 양쪽에 같은 거리의 원형 관문을 둡니다. 지도마다 중심·관문 간격·각도·반경이 다릅니다. |
| 선택 시점 | 시뮬레이션 24틱(1.20초)에 관측소를 고정한 상태로 선택합니다. 화면에는 관문·관측소와 익명 8채널의 고정 부호, 불확실성·누락·신호 나이가 보입니다. 정답, 시드, 원시 관측, 방향 텍스트를 주지 않습니다. |
| 도착 목표 | 중앙에서 정지 상태로 출발해 32틱(1.60초) 안에 닿을 수 있는 **정추력 설정이 더 낮은 관문**을 고릅니다. 평가기는 각 관문 중심을 향해 최대 입력의 0~100%를 5%포인트 간격으로 직접 시험합니다. |
| 방류 목표 | 양쪽 관문에서 각각 표식을 정지 상태로 놓습니다. 같은 32틱 안에 추진 없이 중앙 관측소의 원을 지나는 표식의 출발 관문을 고릅니다. 두 목표 모두 이동 선분이 원에 들어오는 순간을 포함합니다. |
| 채점 가능 조건 | 두 관문 모두 도달 가능하고 최소 추력 차이가 두 눈금(10%포인트) 이상이어야 합니다. 방류한 표식은 한쪽에서만 중앙에 닿고, 두 목표의 유리한 관문은 서로 반대이며 도착에 유리한 쪽은 결정 시점의 실제 흐름 투영 방향과 일치해야 합니다. 제외 사유는 이 순서로 기록합니다. 표시 부호의 정오·세기·누락 여부로 문항을 고르지 않습니다. |
| 비교 전략 | 왼쪽 고정, 오른쪽 고정, 목표만 사용, 부호를 늘 따르기, 늘 거스르기, 화면 움직임과 목표, 부호와 목표입니다. 비교에 쓰는 화면 이력은 사용자가 볼 수 있는 위치입니다. 흐름 추정에는 마지막 세 위치와 고정된 시간 간격·감쇠만 씁니다. 부호 전략은 8개 채널의 세기를 지도 축에 투영합니다. 판독 방향이 없으면 오른쪽 흐름으로 가정합니다. 자유 표류 부표가 보이는 개발 대조도 같은 장면에서 측정합니다. |
| 개발과 확인 | 개발 지도 D1·D2는 각 48개 시드입니다. 확인 지도 C1~C4는 각 80개이며 지도·시드가 겹치지 않습니다. 지도 수치와 시드 시작값은 [문항 코드](gate_task.py)에 고정합니다. 전체 후보와 제외 내역을 저장합니다. |
| 첫 검사 묶음 | 확인 지도마다 양쪽 흐름에서 물리 기준을 통과한 시드 앞 두 개씩, 총 16개 장면을 사용합니다. 같은 장면에 두 목표를 모두 적용해 문항 32개를 검사합니다. A·B형에는 장면당 한 목표만 주고 두 형식에서 목표를 교차합니다. 각 형식은 흐름 방향 × 목표의 네 조합이 4개씩입니다. 양쪽 형식의 제시 순서는 별도 고정 시드로 섞습니다. |
| 판정 | 모든 채점 가능 확인 문항과 A·B형 각각에서 부호와 목표를 쓰는 전략이 75% 이상 맞혀야 합니다. 각 형식에서 이 전략은 고정 관측소의 모든 비교 전략보다 더 많이 맞히고, 화면 움직임과 목표만 쓰는 전략은 50%여야 합니다. 정해진 수를 채우지 못하거나 기준을 넘지 못하면 결과와 부족한 조건을 남깁니다. 이 수치는 소프트웨어 문항 선별 기준입니다. |

시뮬레이터의 숨은 흐름은 물리적 결과를 만들고 평가기가 문항의 적격성을 확인할 때 씁니다. 관측용 추정기와 부호기는 기존 Hidden Flow 경로를 그대로 사용합니다. 목표는 부호가 만들어진 뒤 전략에 주어집니다. 두 목표의 반사실적 시행은 같은 시드·세계 시각·잔여 흐름에서 시작합니다. 소프트웨어가 채점용으로 적용하는 추진은 이후 사람에게 조종을 대신하는 기능이 아닙니다. [기존 동역학과 추정기](../../docs/METHODS.md)

## 첫 확인 뒤 추가한 출제 규칙

최초 확인에서 정해진 첫 16개 장면 중 C1의 한 장면은 선택 시점에 방향을 전혀 표시하지 않았습니다. 기본 방향 추측이 우연히 맞았습니다. 최초 확인의 분모, 점수, 시드 순서, 결과 파일은 그대로 기록합니다. [최초 확인 전에 고정한 설계](https://github.com/hynk-studio/augneta/commit/fe2be484894d3140f23ff7f1c21faa904f418f1a)

첫 사람용 검사에서는 실제로 부호를 읽어야 하는 문항을 제시하기 위해, 예비 시드 실행 전에 다음 교체 규칙을 정했습니다. 부호에서 지도 축 방향을 읽을 수 없는 선정 장면만 교체합니다. 해당 지도에서 기존 시작 시드 + 1000부터 새 시드 80개를 사용합니다. 원래와 같은 물리 기준·흐름 방향을 충족하고 표시 부호에 축 방향 성분이 있는 첫 시드를 채택합니다. 표시 방향과 채점 정답의 일치 여부는 교체 기준에 들어가지 않습니다. 두 형식 모두 기존 자리·목표를 유지합니다. 적합한 예비 시드가 부족하면 해당 자리는 미충족으로 기록합니다. 예비 시드 결과와 최초 확인 결과를 따로 집계합니다.
