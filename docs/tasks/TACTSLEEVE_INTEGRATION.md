# TactSleeve 실행 계획과 도착 후 재개 작업

개정일: 2026-10-15 (UTC)
상태: **장비 독립 선행 개발 진행. 실제 출력·지각·촉각 학습 측정은 장비 도착 후 진행한다.**

이 문서는 [연구 프로토콜](../PROJECT_SELECTION_AND_PROTOCOL.md)의 P1/P2를 TactSleeve 한 쌍으로 시작하는 실행 명세다. 구매·배송·도착·연결은 확인되지 않았다. 문서화가 실물 검증이나 인간 연구 결과를 뜻하지 않는다.

## 1. 결정과 목표 성과물

장비 선택으로 연구 질문을 바꾸지 않는다. 외부 흐름을 촉각 정보로 학습하고, 다른 과제와 나중 세션에서도 활용하며, 인터페이스 변화 후 능력을 보존하는 것이 목표다.

| 성과물 | 목표 | 성립에 필요한 확인 |
| --- | --- | --- |
| 개인 촉각 상태 인터페이스 | 착용·연결 → 짧은 교정 → 개인 프로필 → 훈련 → 새 과제 → 재접속 | 실제 자극, 실제 응답, 직접 조종과 기록이 연결됨 |
| 효율적 개인화·재교정 방법 | 구별하기 어려운 출력에 교정 시간을 집중 | 같은 예산의 단순 방법과 비교하고 별도 검증 자료에서도 효과 확인 |
| 재현 가능한 학습 실험 | 정보 효용·전달 방식·전이·유지·업데이트 손실을 구분 | 비교 조건과 사전 지정 평가, 실패를 포함한 기록, 참가자 단위 해석 |

재착용 교정은 세 성과물 중 일부다. 이를 전체 연구의 최종 목표로 삼지 않는다. 인간 증강이나 신경 변화의 성공을 미리 전제하지 않는다.

## 3. 장치와 실행 경로

공식 제품 사양상 TactSleeve는 **한쪽 3개, 한 쌍 6개의 ERM 모터**와 BLE 연결을 제공한다. 이는 6개 지각 채널이나 8방향 식별 가능성을 보장하지 않는다. 모터 위치·착용 방향·동시 출력의 혼동은 실물에서 확인한다. [제품 사양](https://www.bhaptics.com/ko/shop/buy-tactsuit/tactsleeve/)

첫 실물 경로는 **사용자 PC의 Augneta Python 서버 + 브라우저 UI + bHaptics Player + TactSleeve**로 계획한다. 공식 Python SDK는 Windows 10/11 x64 또는 Apple Silicon macOS, Python 3.8–3.12, 실행 중인 Player와 배포된 haptic app의 App ID/API key를 요구한다. Augneta와 겹치는 Python 3.12를 우선 검토하고 실제 PC에서 버전을 확정한다. SDK의 좌/우 Sleeve 장치 유형은 각각 1/2이며 각 출력 배열은 3개 모터를 다룬다. [SDK 안내](https://docs.bhaptics.com/sdk/python/guide)

개발·코드 검토는 Codex Cloud나 ChatGPT에서 계속할 수 있다. **실물 실행에 로컬 Codex 설치가 필요한 것은 아니다.** 다만 원격 Cloud 서버가 사용자 PC의 BLE 장치를 직접 제어한다고 가정하지 않는다. 브라우저는 조작 화면으로 유지하되, 원격 HTTPS 화면에서 로컬 Player까지 연결하는 방식은 후속 검증 대상이다. 첫 단계에서 이를 위한 새 호스팅이나 터널을 만들지 않는다.

App ID/API key는 bHaptics용 설정이다. 모델 API를 추가하지 않으며, 비밀 값은 로컬 설정에만 두고 Git·브라우저 응답·실험 로그에 넣지 않는다. SDK 설치와 의존성 고정은 재개 작업에서 수행한다. 이번 문서 변경에는 설치·계정 설정·환경 재게시가 포함되지 않는다.

## 4. 먼저 바꿔야 할 출력 모델

`belief → 공통 의미 상태 → 장치별 표현 → 출력 어댑터`를 분리한다. 이것은 제안 설계이며 현재 API가 이미 이 구조라는 뜻은 아니다.

- **공통 의미 상태:** 방향·크기·불확실성·누락 여부와 양자화, 추정기/의미 부호 버전. 목표 위치나 정답 조종 명령은 입력으로 받지 않는다.
- **장치별 표현:** 좌/우 모터의 강도·펄스·휴지기와 개인별 보정. 모터 개수와 의미 범주의 개수를 별도 값으로 둔다.
- **출력 어댑터:** 유한 길이 명령, 중복·만료·연결 해제·일시정지·종료 처리, 호스트 시간 기록. 장치 부재를 성공한 촉각 출력으로 바꾸지 않는다.

첫 후보는 위치로 방향 범주를 나타내는 단순 부호와, 축의 부호/크기를 조합하는 부호다. 실제 모터 배치와 식별 응답을 확인한 뒤 소수 후보를 비교한다. 기존 8방향·4강도나 8→6 중복 매핑을 고정하지 않는다. 필요하면 방향/강도 단계를 줄이고 그 정보량에 시각 비교 조건도 맞춘다. 조합 자극으로 더 많은 범주를 표현할 수 있는지는 검증할 가설이다.

개인화는 먼저 강도·지속시간·휴지기를 조정하고, 학습한 방향의 의미를 유지한다. 평가 조건의 갱신 및 재생 일정은 맞춘다. 의미 자체를 바꾸는 적응은 E2b에서 별도로 시험한다. 신경망이나 LLM을 기본 요건으로 넣지 않고 해석 가능한 고정 부호·단순 이득 보정부터 시작한다.

시각과 촉각은 같은 추정값·양자화·갱신·누락을 사용한다. 펄스 후 휴지기 동안 시각만 계속 새 정보를 제공하지 않도록 공통 전달 일정을 둔다. 불확실성/누락 상태를 촉각으로 안정되게 구별하기 어렵다면 동일한 보조 시각 상태 표시를 두 조건에 제공하고 혼합 방식임을 기록한다. 실제 감각 지연·잔향 차이는 숨기지 않는다.

## 5. 선행 개발과 도착 후 작업

`AGENTS.md`와 최신 상태를 읽고 현재 `main`에서 작업 브랜치를 만든다. 아래 순서를 작은 구현 단위로 진행해 Draft PR로 제안하고 자동 병합은 끈다. 연구 단계 PR-02와 실제 GitHub PR 번호는 같을 필요가 없다.

### 5.0 장비 없이 먼저 진행할 작업

1. 공통 의미 상태와 장치별 출력 표현을 분리하고 6모터 미리보기를 구현한다. 같은 양자화 상태를 시각과 출력 명령으로 표현하는지 검증한다.
2. 교정 응답 화면, 모름/무자극 응답, 중단·저장, 교정/홀드아웃 블록 분리, 프로필 고정·내보내기·불러오기를 구현한다. 화면으로 확인하는 리허설임을 표시하고 실물로 교정된 프로필이라고 부르지 않는다.
3. 다음 작업으로 과제의 정보 효용·난도·지연 민감도와 안전 구역 유지 전이 과제를 점검한다. 합성 정책의 성과와 인간 사용성은 구분한다.
4. 선택적 교정 알고리즘의 모의 비교는 후속으로 남긴다. 가상 사용자의 혼동 모델에 맞춘 성과를 인간에게 일반화하지 않는다.

이번 구현의 우선 완료 범위는 1·2다. 물리 드라이버, 실제 강도/위치 구별 측정, 촉각 학습 실험은 장비 도착 이후 범위다. 기존 ChatGPT Site는 데모로 사용할 수 있지만 GitHub 변경이 자동으로 배포되지는 않는다. 새 기능의 Site 반영과 실제 PC 실행은 각각 확인한다. 첫 실물 호스트는 Windows PC를 우선하고 Apple Silicon 맥은 대안으로 둔다. 로컬 Codex 설치는 요구하지 않는다.

### 5.1 사용 PC와 실물 출력 확인

1. 실제 모델/좌우 구성, PC/OS, Player/SDK/Python 버전과 페어링 상태를 확인한다.
2. 모터 인덱스와 착용 위치의 대응을 실물로 기록하고 좌우 각각의 출력·정지를 확인한다. 추측한 몸 위치를 코드에 고정하지 않는다.
3. 짧은 유한 출력과 명시적인 사용자 시작/중단을 구현한다. 연결 해제·오류·화면 이탈·정지 시 추가 재생을 멈추고 재연결 시 자동 재생하지 않는다. SDK 호출이 막혀도 무한 자극이 남지 않도록 유한 명령과 만료 처리를 검증한다.
4. 시뮬레이션 tick과 실제 호스트 단조 시간, 명령 생성/전송/SDK 반환을 구분한다. 현재 HTTP 왕복에 따른 시뮬레이션 지연을 실물 시간 측정으로 간주하지 않는다.

SDK의 `play_dot`는 모터별 강도와 명령 지속시간을 받고, 반환값은 요청 ID 또는 실패 값이다. 이 반환은 피부 자극 시작 시각이 아니다. [API 참고](https://docs.bhaptics.com/sdk/python/references)

피부 수준 지연·지터를 주장하려면 별도 측정 방법과 분해능을 기록한다. 측정이 없으면 미측정으로 남긴다. 기존 모의 출력의 시간 만료 검사만으로 실제 정지 장치가 검증되었다고 하지 않는다.

### 5.2 실제 응답을 받는 교정

- 단일 위치와 소수 조합, 강도 단계의 구별을 확인한다. 무자극 시행, 모름/못 느낌, 응답 시간, 중단/불편을 기록한다. 제조사 사용 지침과 사용자가 편안하게 구별하는 범위 안에서 시작한다.
- 프로필을 정하는 교정 블록과 그 성능을 확인하는 홀드아웃 블록을 분리한다. 같은 응답을 맞추고 평가에 다시 쓰지 않는다.
- 실제로 구별 가능한 범주 수·강도·시간을 결정한다. 사용 위치/착용 방법, 의미 부호, 물리 보정, 장치/SDK 버전을 함께 저장한다.
- 고정 순서 또는 균등 탐색을 기준선으로 두고, 어려운 구분에 질문을 더 배정하는 선택적 교정은 후속 비교로 추가한다. 방법 간 교정 시간 또는 응답 예산을 사전에 맞춘다.
- 최초 교정과 재착용 후 교정을 구분한다. 평가 블록 중 프로필을 바꾸지 않는다.

현재 모의 교정 계획의 72개 예정 시행은 실제 응답이나 표준 표본수가 아니다. 장치 식별성·피로를 확인해 시행 구성을 정하고, 기준선과 선택적 방법을 비교할 때 같은 기준을 적용한다.

### 5.3 기존 숨은 흐름 과제 연결

개인 프로필을 고정한 뒤 기존 직접 조종 과제에서 짧은 개발자 파일럿을 수행한다. 없음·동일 정보 시각·고정 촉각·개인화 촉각의 조건 정의를 분리하고, 이 첫 연결 확인을 학습 효과 실험으로 보고하지 않는다. WASD는 유지한다. AI 자동 조종이나 EEG/EMG 입력 교체를 이 작업에 섞지 않는다.

### 첫 작업의 완료 기준

- 실제 좌우 출력과 정지 경로, 연결 실패 처리가 확인되고 결과/실패가 기록됨.
- 실제 교정 응답과 별도 검증 결과로 프로필을 만들고 다시 불러올 수 있음.
- 기존 과제에서 직접 조종과 시각/촉각 전달 일정의 대응을 확인함.
- 명령·실제 측정·개발자 관측·연구 참가자 자료를 구분하는 기록이 있음.

이는 장기 학습·전이·인간 증강의 완료 기준이 아니다. 식별이 불충분하면 부호를 단순화하고 재검증한다. 이 장치에서 유용한 정보를 전달할 수 없다는 결과도 남기며, 그때 다른 출력 장치를 검토한다.

E1의 주 평가변수 후보와 주 비교는 [프로토콜](../PROJECT_SELECTION_AND_PROTOCOL.md)에 따른다. 파일럿 뒤 확증 실험 전에 주 비교, 평가 시간, 결측/중단 처리, 최소 관심 효과를 고정한다. 시각 부담 감소를 시험하려면 추적 성능 허용 범위와 이중과제 평가를 별도로 사전 지정한다. 결과를 보고 성공 기준을 바꾸지 않는다.

교정 자료와 검증 자료, 훈련과 전이, 새 세션 자료를 분리한다. 한 사람의 수천 시점을 참가자 수로 세지 않는다. 자기 실험은 실행 가능성 탐색으로 한정하고, 사람 간 일반화는 별도의 연구 설계와 자료가 필요하다. P3 생체신호 연구는 독립 트랙으로 유지하되 현재 출력·교정 개발 다음의 작업으로 남긴다.

## 7. 기록과 증거의 경계

- 기존 합성 기록의 `human_evidence=false`, `hardware_verified=false`를 그대로 보존한다.
- 실물/인간 관측을 위한 기록 스키마는 별도 구현한다. 현재 소프트웨어 전용 검사를 우회하거나 SDK 성공만으로 두 플래그를 일괄 변경하지 않는다.
- 구현 시 `participant_kind`, 관측 종류, 장치 출력 확인 방법/범위, 측정하지 않은 항목을 함께 기록한다. 개발자 지각 응답도 합성 자료와 구별하지만 참가자 연구의 일반화 근거로 확대하지 않는다.
- 추정기, 의미 부호, 물리 출력 프로필, 실제 명령, 시간 기준, 변화 이벤트를 각각 식별한다. 결정론적 명령 재생은 동일한 물리 자극이나 지각의 재현을 보장하지 않는다.
- 개인 응답·기록은 Git에서 제외하고, 연구 수집 범위와 저장/공유 조건을 해당 작업에서 명확히 한다. 기존 프로토콜의 연구윤리·동의·해석 기준을 유지한다.

## 8. 현재 작업과 실물 재개 메모

이번 변경의 범위는 README·연구 프로토콜·이 실행 명세다. 추가 코드, 테스트, 의존성, 장치 설정, Cloud 환경 게시를 변경하지 않는다. 이전 테스트 수치를 이번 문서 작업에서 새로 실행한 결과처럼 보고하지 않는다.

**지금은 5.0의 1·2를 개발하고, 장비가 도착하면 5.1부터 실물 확인을 진행한다.** 그때 필요한 시작 정보는 실제 좌우 장치 구성과 사용할 PC/OS다. 이전의 전면 보류 결정을 이 진행/대기 구분으로 대체한다. P3나 장기 신경 인터페이스 연구의 범위를 삭제하는 결정은 아니다.
