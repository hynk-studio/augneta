# PR-02 출력 계약과 교정 절차

목적은 추정한 환경 정보를 사람이 구별할 수 있는 감각 입력으로 전달할 준비를
하는 것이다. 게임 점수 향상, 감각 확장, 학습 전이는 이후 검증할 질문이다.
이 문서의 본문은 **기존 8슬롯 출력 mock과 운영자용 교정 계획 생성기**를 설명한다.
2026-10-15에 추가한 6슬롯 의미/출력 분리와 화면 교정 리허설은
[선행 개발 안내](PREARRIVAL_PREPARATION.md)에 있다. 실제 참가자용 촉각 출력·교정과
전체 PR-02의 물리적 완료 조건은 남아 있다. 아래의 8방향·4강도는 기존 mock의
설정이며 TactSleeve에서 달성해야 할 지각 채널 수가 아니다.

## 실행

기존 잠금 의존성으로 설치한 저장소에서 실행한다. 새 패키지는 없다.

```bash
.venv/bin/python -m augneta haptic-smoke --out runs/haptic-smoke --seed 7
.venv/bin/python -m augneta replay runs/haptic-smoke/tracking
.venv/bin/python -m augneta calibration-plan --out runs/calibration-plan --seed 7 --blocks 2
```

출력 폴더는 새 경로여야 한다. `haptic-smoke`는 기본 600단계 과제의 실제 인과
추정 패킷을 mock으로 보내고, 명령·종료 이벤트와 원본 과제 기록을 저장한다.
시간은 합성 밀리초다. 물리적 장치·브라우저·네트워크 지연을 측정하지 않는다.
합성 정책은 원래의 held packet을 사용한다. 따라서 `tracking/summary.json`의
RMSE는 촉각 조건의 수행 점수가 아니다. `--output hardware`는 명시적으로 실패한다.

`calibration-plan`은 정답을 포함한 운영자 전용 `plan.json`과 비어 있는
`responses.json`을 만든다. 참가자에게 정답 파일을 보여 주지 않는다. 파일을
생성했다고 자극 제시·응답 수집·교정을 시행한 것으로 기록하지 않는다.

## 패킷에서 출력까지

| 층 | 구현·의미 |
| --- | --- |
| 추정기·encoder | 기존 `rw-kalman-*` → `polar8-*`; 숨은 정답·목표·행동 입력 없음 |
| 의미 패킷 | 방향 8구간, 세기 0–4, 불확실성, sample age, 지연·누락, 독립 component ID |
| 출력 프로파일 | 8개 논리 채널을 서로 다른 액추에이터 슬롯에 대응. 채널별 0+4단계 명령값, 별도 ID/SHA-256 |
| 프레임 | 원본 의미 패킷과 보정한 액추에이터 명령값을 함께 보존 |
| mock 전달 | 명시적 arm, 세션 epoch, 순번, 제한된 펄스, 만료와 중단 기록 |
| 실물 전달 | 아직 없음. 모델별 드라이버·출력·타이밍 확인 후 별도 구현 |

부호 회전은 encoder에 남는다. 출력 프로파일은 이미 회전된 논리 채널을 실제
슬롯으로 옮기며 방향을 재해석하지 않는다. 프로파일은 `OutputProfile`로 만들고
`to_dict()/from_dict()`로 보존할 수 있다. 채널 합치기, 범위 밖 명령, 같거나
역전된 세기 단계는 거부한다. 기본 정규화 명령 `0,.25,.5,.75,1`은 **mock 값**이며
착용자에게 안전하거나 편안한 출력 크기라는 뜻이 아니다.

## 전달 시간과 중단

기본 mock은 펄스 100 ms, 패킷 신선도 한도 250 ms다. 이는 소프트웨어 시험용
선택이며 실물에 대한 권장 수치나 검증된 지각 한계가 아니다.

- 새 패킷 한 개가 한 번만 펄스를 만든다. 동일/이전 step은 펄스를 연장하지 않는다.
- 신선도는 패킷 emission부터 계산한다. 추정기에 사용된 센서 샘플의 age와 다르다.
- 허용 신선도가 먼저 끝나면 펄스도 그때 끝난다. 오래된 명령을 큐로 재생하지 않는다.
- stop/pause/disconnect는 출력 프레임을 지우고 disarm한다. 새 arm 전에는 재개하지 않는다.
- 이전 epoch의 콜백은 새 세션에서도 거부한다. 잘못된 패킷·미래 emission·시계 역행은 중단한다.
- `tick()`이 호출되어야 mock 만료가 처리된다. 이 코드는 실물 watchdog이 아니다.
  tick 사이를 건너뛰면 로그는 예정 만료와 만료를 확인한 시각을 각각 보존한다.

명령 로그의 `mock_accepted_at_ms`는 모의 수신 시각이다. transport ACK,
device ACK, 측정한 onset은 각각 별도 `null` 필드다. 이 중 어떤 ACK도 실제
피부 접촉면의 진동 시작을 뜻하지 않는다. 부동소수점 simulation seconds는
`step * dt_s * 1000`으로 변환하며 장치 시계와 직접 빼지 않는다.

## 동일 정보 시각 비교

준비된 `active_frame.feedback_packet`은 원본 의미 패킷과 정확히 같다. mock이
만료·중단되면 이 프레임도 사라진다. 이 공통 프레임은 향후 두 제시 방식의
시작·종료를 맞추기 위한 소프트웨어 경계다. **기존 웹 dashboard는 아직 이
펄스 게이트를 사용하지 않는다.** 현재 화면과 mock을 이미 맞춘 물리 비교라고
보고하지 않는다.

실물 UI에서는 방향·세기만 시각 또는 촉각으로 제시하고, 불확실성·age·누락 등
부가정보는 두 조건에 같은 공통 표시로 제공한다. 장치가 받는 정보가 적다면
시각 조건의 정보도 동일하게 제한하거나 차이를 명시한다. 촉각 조건에 방향 정답
그림을 함께 보여 주면 순수한 촉각 비교가 되지 않는다.

명령 시각을 맞추는 것과 실제 전달을 맞추는 것은 다르다. 진동 센서/가속도 센서로
물리 출력을, 화면에는 필요하면 광센서로 실제 표시를 같은 측정 시간축에 기록한다.
장치별 수송 지연과 표시 지연을 구한 뒤 공통 지연을 설정하고 다시 측정한다.
늦은 출력·누락은 제외하지 않고 별도로 집계한다. 정보·양자화·업데이트 주기·공통
부가정보가 맞는지, 측정 지연 차이가 정한 허용 범위 안인지 확인한 후 비교한다.

## 지각 교정 절차: 아직 시행하지 않은 프로토콜

1. **장치 기록과 bench 측정.** 모델, firmware/SDK, 프로파일 해시, 실제 모터
   인덱스와 착용 위치를 기록한다. 미착용 상태에서 개별 출력·종료·연결 해제를
   확인한다. 장치 명령 허용값과 착용자 편안함을 따로 취급한다.
2. **개인별 출력 확인.** 수행 범위와 중단 방법을 설명하고 착용자가 언제든
   멈추거나 벗을 수 있게 한다. 제조사 범위 안에서 위치별 감지와 편안한 출력을
   확인해 네 단계 후보를 만든다. 숫자를 선형 증가시켰다고 감각 간격이 같다고
   가정하지 않는다. 불편·구별 실패는 보존한다.
3. **부호 설명과 연습.** 위치와 세기의 응답 방식을 익히는 구간은 assessment와
   구분한다. 게임 목표·추적 점수는 사용하지 않는다. 모든 문항은 응답 또는 명시적
   skip 이후 진행하고 휴식을 허용한다.
4. **가려진 식별 블록.** 정답을 숨기고 8개 위치 × 4개 세기 각 한 번과 무출력
   4문항을 블록 안에서 섞는다. 기본 2블록은 72문항이며 통계적 표본수 근거가
   아니다. 위치·세기 및 ‘구별 못함’을 응답한다. 응답 키·질문은 조건 간 고정한다.
5. **분석과 재교정.** 위치 혼동표, 세기 혼동표, 무출력 오탐, 누락을 함께 본다.
   반복해서 혼동되는 위치/단계는 프로파일 또는 부호를 새 버전으로 수정한다.
   수정용 블록과 새 시드의 확인 블록을 분리하며 같은 답안으로 보정·검증하지 않는다.
6. **고정과 이전.** 프로파일을 고정한 뒤 원래 과제로 옮긴다. 구별하기 쉬워졌다는
   결과를 전이·장기 학습 결과로 해석하지 않는다. 해당 결과는 PR-03에서 검증한다.

계획의 순서는 seed로 재현되고 블록마다 문항 수가 균형을 이룬다. 참가자 간
조건 순서 균형화는 별도 설계이며 아직 구현하지 않았다. 계획은 프로파일의
전체 내용과 해시를 포함하므로 다른 위치 배치로 조용히 바꿀 수 없다.

분석 함수는 `augneta.calibration.score_responses(plan, responses)`다. 응답은
`trial_id`, `channel`(0–7 또는 null), `level`(0–4 또는 null)만 받는다.
응답 행 자체가 없으면 누락이고, null은 명시적인 ‘구별 못함’이다. 무출력 정답은
`channel=null, level=0`이다. 중복·모르는 trial ID·변경된 계획은 거부한다.

위치 혼동표는 정답 8행 × 응답 9열(마지막은 구별 못함), 세기는 정답 5행 ×
응답 6열이다. 누락은 이 표에 가짜 응답으로 넣지 않고 따로 보고한다. 응답한
문항 기준 정확도와 계획 전체 기준 정확도를 같이 내며 빈 응답을 성공으로
처리하지 않는다. 함수 결과는 기술 통계다. 호출자는 실제 응답 출처를 별도로
기록해야 하며 합성 unit test를 사람의 식별 성능으로 보고할 수 없다.

## 실제 출력 검증 기록의 필수 항목

| 기록 | 해석 |
| --- | --- |
| packet emission, host enqueue/send, 수송·장치 ACK | 각각 다른 사건; clock ID와 단위 필요 |
| 액추에이터별 측정 onset/offset 및 파형 | command와 분리된 물리적 전달 자료 |
| 명령/프로파일/장치 식별자 | 어느 명령이 어느 물리 파형과 대응하는지 |
| 지연 p50/p95/max, 누락, 중복, 종료 후 잔여 출력 | 평균 지연만으로 정상 작동을 판단하지 않음 |
| 탭 숨김·정지·재연결·host 종료 조건 | 재시작 시 자동 출력 금지; 명시적 재시작과 장치측 만료 확인 |
| 시계 대응·측정 장비·분석 코드·원본 로그 | 장치와 host 시간이 다를 때 동기화/불확실성 기록 |

현재는 이 측정값이 없다. 코드의 상한이나 SDK의 duration 인자가 실제 종료를
증명하지 않는다. 첫 bench 측정 후 허용 지연·종료 기준을 고정하고, 사람 대상
식별 자료를 모으기 전에 다시 검사한다.

## 기록과 개인정보

현재 CLI는 이름·연락처·장치 식별자를 수집하지 않으며 참가자 응답을 생성하지
않는다. `runs/`는 Git에서 제외한다. 향후 사람 자료는 가명 세션 ID로 분리하고,
동의·접근·보관·삭제 범위를 정한 뒤 수집한다. 공개 PR에 실제 응답이나 기기
고유 식별자를 올리지 않는다. 자동 클라우드 업로드는 이 도구에 없다.

기존 replay는 전체 구현 해시와 Python 버전을 확인한다. 이번 모듈 추가로
과거 소스 해시와 달라지므로 PR-01 기록은 원래 commit과 Python으로 재생한다.
새 `output_events.jsonl`은 합성 전달 trace이며 현재 replay가 검증하는 대상은
`tracking/`의 원본 과제다. 전달 trace의 실물 재현이나 별도 replay를 주장하지 않는다.
